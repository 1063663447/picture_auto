# 9.6.4 · 修：「基准图还没出，对话框就说基准已确认」

日期：2026-11-11。前端逻辑修正，**刷新页面即可**（后端未改，服务已重启过）；资源 `?v=9.6.9`。

## 现象（客户截图）

```
AI 助手：这是这批的基准图。满意就说「可以」…
AI 助手：基准已确认，正在按它给其余颜色改色：0/11
```

基准图一张都没出来，对话框直接进入「已确认 + 改色中」，而且从头到尾没把图返给用户。

## 根因

`masterWatch` 把「`review.awaiting` 为假」当成了「已经确认过」。但任务**刚创建**时
（基准还在排队/生成）`review.awaiting` 同样是假，于是直接掉进「改色进度」分支：

| 状态 | awaiting | phase | 基准有图 | 判成「已确认」 |
|---|---|---|---|---|
| 刚创建、基准生成中 | false | `""` | ❌ | ← 旧代码在这里出错 |
| 基准出完、等确认 | **true** | `""` | ✅ | 否（正确） |
| 已确认、改色中 | false | `derived` | ✅ | 是（正确） |

「已确认」不能只看 awaiting，要认 `phase === "derived"` 或 `approved_ids` 非空。

## 改法

- 加了显式状态机（按顺序判断，不再靠单个布尔）：
  1. `approved`（`phase=derived` 或 `approved_ids` 非空）→ 才显示「基准已确认，按它改色 x/N」；
  2. `awaitingReview && 有基准图` → 返图卡片 + 「就按这张改色 / 我要改…」；
  3. 基准任务还没出全 → 只报进度「基准图生成中 i/N（生成中 k）」/「失败 m，可重试」，
     **不发图、不提确认**；
  4. 任务以失败/取消结束且没有基准图 → 直说「基准图没出来：<原因>，可以重试或换模型」。
- 开场白也按「有没有基准图」分开说：没图时说「基准图正在生成（先只出一张，其它 N 个颜色还没开始）」，
  不再假装图已经在。
- 没出图时重置 `masterShown`，保证真的出图后还会发一次。
- 轮询节奏：没出基准 2s 一次，出图后 3s。

## 回归

新增 `python tools/check_master_chat.py`：

- **后端把三种状态量出来**，证明 `awaiting=False` 不能当「已确认」：
  刚创建（awaiting=False / phase 空 / 基准无图）→ 出完基准（awaiting=True / phase 仍空 / 有图）
  → 确认（phase=derived / approved_ids 非空）；
- **静态检查前端**：确实用 `phase/approved_ids` 判已确认、三个分支顺序正确、
  生成中有独立文案、没出图会重置返图标记、开场白区分有无基准图。

## 需要你注意

- 你截图里那一批的 11 个颜色：**确认前的基准图那 1 张已经在跑**，其它颜色确实还没开始
  （`0/11` 里的 0 是派生色，不含基准）—— 现在文案会明确写成「基准图生成中 0/1」，
  出图后直接返图给你，你确认之后才会出现「按它给其余 11 个颜色改色」。
- 这次只改了前端，**Ctrl+F5** 刷新即可看到修复后的对话。
