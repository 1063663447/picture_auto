# 9.6.33 · 白色更白 + 基准图改成「取消这款」

## 1. 白色不够白（有点像灰色）
客户原话：「目前很多款式的白色都不够白，有点像灰色」。

原因：白款的色号是 `#E6E6E8`，但提示词里只有「目标色 ≈ #E6E6E8」这一句，
模型会顺着原图/场景的环境光把整件压成浅灰（尤其人像上身、暖光背景）。

改法（`prompts.py`）：新增 **WHITE COLOURWAY** 条款，白色系**所有路径**都注入
（一次到位 / 派生色·色卡 / 派生色·效果图 / 只换色）：

> 受光面接近纸白（#FFFFFF 附近），高光保持白，阴影中性（最多略冷）；
> 不许画成浅灰 / 灰烬灰 / 奶白 / 米白 / 象牙 / 米黄 / 蓝灰；
> 不许继承原图的环境色偏和曝光衰减，也不许为了融进场景把衣服压暗。

判定用 `is_white_colour()`：label=white / 中文名「白色」/ 色号最暗通道 ≥205 且三通道差 ≤16，
所以杏色、花灰这些浅色不会被误带。

### 真机验证（terra · gpt-image-2.6-sunburst）
用客户那张白罗纹短袖当原图，取衣服主体区域（避开印花）统计中性像素亮度：

| 版本 | 平均亮度 | P90 |
|---|---|---|
| 原图 | 230.0 | 236 |
| **改之前** | **222.8** | 232 |
| **改之后** | **237.3** | 242 |

对照图：`scratch/white-9.6.33/white-compare.png`。

顺手补了一条：`PRINT LOCK` 加上「源图是空白的就保持空白，不许自己发明印花/字母/旗标」
—— 验证时刚好碰到一次模型给空白白T恤画上了「NEW YORK · U.S.A.」印花，加完这条再跑就是干净的。

## 2. 基准图的「暂停」改成「取消这款」
客户原话：「基准图的暂停逻辑改成取消，取消后本次任务取消对应款式的生成，并且该基准图和
该款式待生成图片不显示」。

- 审核条卡片上的按钮：`暂停` → **`取消这款`**（两步确认，点别处复原）
- 后端 `cancel_style(job_id, task_ids)`：
  * 这张基准图 → `status=canceled` + `hidden=True`（成品文件保留，历史里还在）
  * 该款**还没开始**的颜色 → 一起 `canceled + hidden`（已经出图的留着，钱已经花了）
  * 其它款式完全不受影响；所有款都取消干净时任务收尾成 partial
- `Task.hidden` 落盘；`counts()` 跳过 hidden（「全部 / 已完成」这些数字不再算它）
- `review.pending_ids` / `paused_ids` 也排除 hidden，审核条不会再要求确认它
- 前端：成品网格和审核条都过滤 `hidden`，卡片直接不渲染

暂停功能本身保留在**普通成品卡**上（单张 / 多张 / 工具栏「暂停选中」），只是基准图的出口改成取消。

### 真机验证
2 个款式（06 连帽卫衣、10 弹力短袖）各 2 色 → 停在审核 → 点「取消这款」（两步）：
审核条从「2 张待确认」变「1 张待确认」，06 那张卡和它没开始的颜色直接消失，
顶部计数从「全部 4 / 已完成 2」变「全部 2 / 已完成 1」，1/2 进度，剩下的 10 弹力短袖照常。
