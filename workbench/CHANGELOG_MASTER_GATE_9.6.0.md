# 9.6.0 · 先出基准图 → 对话确认/修改 → 按基准改色 → 沉淀款式规则

日期：2026-11-11。后端 + 前端 + 数据改动，**需重启服务**；前端资源 `?v=9.6.4`（Ctrl+F5）。

客户要求（原话）：

> 现在生图逻辑改为：先出基准图，提供确定和修改功能通过 harness 与用户对齐，最终排版再以基准图进行改色
> 减少错误率，并且根据对齐结果来沉淀迭代对应款式的 skill；……提供一个 AI 助手，以对话框形式来做改图、
> 需求对齐、改色等动作，尽量还原他们在 codex 上直接对话改图的操作（但保留我们的原生系统），
> 注意配好 harness 各项工具和上下文。

## 一、生成流程：基准图闸门（review gate）

以前是一口气把同款所有颜色都出完（先出基准色、其余派生，但**中间不落**）。
现在多了一道闸门：

```
提交 → 只出「基准图」→ 任务停在 review（等你确认，不打包、不派生）
        ├─ 确定 → 按这张基准图给其余颜色改色（派生色发基准成品 + 面料色卡）
        └─ 说哪里要改 → 生成改图任务；改好后「采纳」回来再确认
```

- `Job.params.review_gate`（默认开，`defaults.review_master` 可关）：**只有多色批次**才开；
  单色批次没有派生色，自动关掉。
- 任务状态新增 `review`：`job.status` / `job.stage` / `job.review` 三个地方都能看到
  （待确认几张、已确认几张、其余颜色改到几成）。
- 确认前**不会花派生色那笔钱**；确认后只跑没出图的任务（`open_tasks` 过滤），
  重复点「开始」不会把已经出好的图再买一次。
- 新增接口：
  - `POST /api/jobs/{id}/approve` —— 确认基准图并开始改色（可带 `note`、`adopt`、`learn`）
  - `POST /api/jobs/{id}/reject` —— 基准图不满意，按一句话生成改图任务
  - `POST /api/jobs` 新增可选 `review_master=true|false`
- 采纳（adopt）：把「对话框里改完的那张」或另一批的成品复制过来当新基准，
  记录 `task.adopted_from = "<job>::<task>"`，再确认即按新图派生。

## 二、款式记忆：对齐结果沉淀成 skill（style lessons）

- 新增 `skillbridge/style_memory.py`：把「审核时确认过的要求」写进
  `library/prompts/<slug>.json` 的 `lessons` 数组（**同一个款式一个文件**，运营打开就能看到）。
  每条含 `id` / `clause`（注入提示词那句）/ `zh`（运营原话）/ `source` / `created_at` / `hits`。
- 注入位置：`prompts.style_positive()` 在款式核心后面追加
  `STYLE RULES LEARNED FROM PREVIOUS APPROVED BATCHES …`（最多 6 条，避免稀释重点）。
- 去重：同一句话再说一次只累加 `hits`，不重复注入；上限 12 条，自动淘汰最旧的。
- 翻译：用 harness 的对话模型把中文要求提炼成一句英文约束（`distill_online`）；
  模型不可用时回落成 `Operator-confirmed rule for this style (apply it by default): <原话>`，
  **绝不因为翻译失败而丢掉规则**。
- 接口：`GET/POST /api/styles/{slug}/lessons`、`DELETE /api/styles/{slug}/lessons/{id}`。

## 三、AI 助手（对话框）新增能力

| 工具 | 干什么 | 什么时候用 |
|---|---|---|
| `master_status` | 基准图状态（待确认/已确认、派生进度） | 用户问「到哪了/还要多久」 |
| `approve_master` | 确认基准图 → 按它改色（**产生费用**） | 用户说「可以 / 就这样 / 确定」 |
| `reject_master` | 按一句话生成改图任务 | 用户说「领口小点 / 颜色偏了」 |
| `get_style_skill` | 看这个款式现在的规则（提示词要点 + 已记住的规则） | 判断要不要补规则 |
| `save_style_rule` | 记一条长期规则（下次同款直接带上） | 用户说「记住，以后都这样」 |

- 新模式 `mode="master"`：`POST /api/harness/stream` 支持，需带 `job_id`。
  开场上下文会写明「基准图待用户确认 + 其余颜色 0/2」；附图带**基准图 + 原始上传图**。
- 系统提示词新增「基准图优先的工作方式」：不要催、不要替用户确认；新手语气；一次只问一句；
  一次性要求不记进规则；报价先看还剩几张。
- 拦截：非审核期调用审核工具会被拒；过短规则、空修改要求都会被挡下。

## 四、界面

- 画布顶部新增**基准图审核条**（`#reviewBar`）：基准图缩略图（点开看大图）+ 「确定，按它改色」
  + 「说要改哪里（对话）」+ 一句「确认前不会出其它颜色，也不花钱」。
- 「说要改哪里（对话）」直接打开对话框的 **master 模式**：标题「AI 基准图确认」，
  开场白说明「满意就说可以」，下面 5 个一键话术（可以/领口小一点/颜色偏了/印花别动/记住这条）。
- 对话框在 review 状态下可以正常发送（以前会被「本轮任务仍在运行」挡住）。
- 原生流程全部保留：改图、批量导出、提示词预览、历史任务、飞书补写都没动。

## 五、自检

```powershell
python tools/check_master_gate.py     # 闸门：只出基准 → 确认 → 按基准改色 → 沉淀 → 打回 → 采纳
python tools/check_assistant.py       # 对话框：工具齐不齐、master 上下文、分发与拦截
python tools/selftest.py              # 主自检（多色批次会自动走完两段）
python tools/check_multi_style.py     # 多款式导出
python tools/make_review_fixture.py   # 造一个「基准待确认」假任务用于界面验收（不花钱、不写飞书）
```

`check_master_gate.py` 用「记录型接口」证明：

1. 多色任务只发基准那一次请求，任务停在 `review`，派生色一张没发；
2. 重复点开始不会重复计费；确认后只跑派生色，且**第 1 张图必须是确认过的基准成品**（+ 面料色卡）；
3. 确认备注进了该款式的 lessons，下次生成的提示词里自动带上，同一句不重复追加；
4. 打回生成改图任务、原任务继续等确认；「采纳」能把改好的图变成新基准再派生。

## 六、已知限制

- 闸门只管**多色批次**：单色任务一次出完（没有派生色，没有审核意义）。
- `review` 不算终态：这时点其它「开始生成」仍会被拦（先确认或取消这一批），
  对话框与审核条可以正常操作。
- `lessons` 是「运营认可过的要求」，不是自动学习：只有点了确认并写了备注（或对话里说「记住」）
  才会沉淀；一次性要求不会进规则。
- 中文原话在翻译不可用时会被原文注入提示词（混排），比丢掉规则更安全。
